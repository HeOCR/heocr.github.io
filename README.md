# heocr.github.io

The one-page project site for HeOCR: https://heocr.org

It is static HTML. Hebrew is the default language: `index.html`, `benchmarks.html`, `htext.html`, `download.html`, `rights.html`, `privacy.html`, `datasets.html` (from `scripts/build_datasets.py`) and `code-signing.html` (from `scripts/build_code_signing.py`) at the root are Hebrew, and the same pages in English are under `en/`. A toggle at the top of each page switches language. The old Hebrew URLs (`he/*.html`) are small redirect pages to the root, generated by `scripts/build_redirects.py` (`--check` as with the others). `scripts/crawl_links.py` crawls a local server (`python3 -m http.server`) and reports broken internal links. GitHub Pages serves it from `main`.

## Design and shell

The site uses the "Bounding Box" brand. The handover (brand guide, tokens, logo files, reference pages) is in
`design/brand-handover/`; read its `README.md`, `BRAND.md` and `site/MARKUP.md` before changing the look.

- `site.css` and `theme.js` at the root are the handover's, used as delivered: one stylesheet for every page, EN and HE.
  Light is the default whatever the OS setting; night mode only through the toggle, remembered under `heocr-theme`.
- `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` come from `design/brand-handover/logo/`. The link-preview images `og-image-he-1200x630.png` (Hebrew pages) and `og-image-en-1200x630.png` (English pages) come from `design/asset-pack/og/`; `og-image-1200x630.png` is a copy of the English one, kept for old links.
- `scripts/shell.py` is the one source for the head, header (logo, navigation, language switch, theme toggle), footer,
  boxed page title and page index. The generated pages call it; the hand-written pages (`index.html`, `rights.html`,
  EN and HE) carry its blocks between `<!-- shell:… -->` markers, kept in sync by:

```
python3 scripts/apply_shell.py           # rewrite the shell blocks of the hand-written pages
python3 scripts/apply_shell.py --check   # fails if a hand-written page's shell differs from shell.py
```

The home page's introduction and model release status are maintained by `scripts/apply_shell.py`. Run the builder for changes to those sections.

## Dataset catalog

The Hebrew and English homepages use the pinned Hub releases in
`datasets/catalog.json`. The catalog sums published counts across releases.
If a count is unavailable, leave it null. Keep partial counts scoped to their
published component. Verify Zenodo links against the matching release.
The `collections` lists set the main cards for real images and text. Other
datasets in those groups appear under a closed source disclosure. A collection
slot without a matching dataset row shows publication pending. Add its dataset
row once its revision, licence and counts are verified. Set
`duplicates_sources: true` for a collection that repackages counted sources.
It adds one repository to the dataset count and contributes no additional
content totals. Mark a preserved older release `superseded` to keep its links
available and exclude its counts from the content totals.

```
python3 scripts/build_datasets.py
python3 scripts/build_datasets.py --check
```

## Benchmarks page

The P-mod-open v0 benchmark and methodology pages are generated in Hebrew and English
from the pinned [published scores](benchmarks/pmod-open-v0-scores.json). Regenerate the
four checked-in pages with the standard builder.

```
python3 scripts/build_benchmarks.py
python3 scripts/build_benchmarks.py --check
```

The pages use registered held-out measurements on real documents and photographs.
The v0 dataset, redistribution scope, and exact score definitions are documented
in [the published benchmark dataset](https://huggingface.co/datasets/HeOCR/p-mod-open-v0).

The maintainer approved the four new Hebrew release-status strings on 2026-11-20: “All strings approved”.

The download status pages are also generated:

```
python3 scripts/build_download.py
python3 scripts/build_download.py --check
```

## htext page

`htext.html` and `en/htext.html` describe the [htext](https://github.com/HeOCR/htext) Hebrew text dataset and its three releases (CC0, CC BY, CC BY-SA). They
are generated from one file, `htext/corpora.json`; do not edit the two pages by hand. When htext publishes a corpus or a
new version, add or update its entry in `corpora.json`, or refresh an existing entry's counts from its corpus card:

```
python3 scripts/build_htext.py --import-card pby path/to/htext/data/pby/v1/corpus_card.json
python3 scripts/build_htext.py           # writes both pages (standard library only)
python3 scripts/build_htext.py --check   # fails if a committed page or htext/line_counts.json does not match corpora.json
```

The builder also writes `htext/line_counts.json`: the one line-count rule for htext, shared with the home page and
datasets. Per HF repository (`repositories["HeOCR/htext-…"]`): `lines`, `unpointed`, `pointed`, `by_subset` and
`releases`, summed over live releases and leaving out the Israel + US subset variant. Other builders should read
htext counts from there.

### Benchmark release staging

Build the bilingual release pages outside the checkout. Without results, this renders the layout preview.

```bash
python3 scripts/build_release_benchmark.py --out-dir ../preview
python3 scripts/build_release_benchmark.py --out-dir ../preview --check
```

For a release preview, add `--release-data /path/to/approved-aggregates.json --sha256 <digest>` to both commands.
The builder accepts eval's `heocr.benchmark.scores.v1` export, containing page CER and WER for ten
readers in both registered views, per carrier and pooled. It renders the registered P-mod-open v0 figures. The closed table reserves space for future published results.
It validates the reader and carrier panels, denominator arithmetic, and byte identity before rendering.
The public tables distinguish the two phone streams with the aliases Phone A and Phone B.

Once the redistribution scope is approved, add `--public-pages <count>` to render the dataset link and
disclose any exclusions from the public copy. Scores always use the registered measurement scope.
Review the exact staged pages and Hugging Face artifact together before publishing.

## Build the leaderboard

The bilingual leaderboard uses the external reader aggregates in
`leaderboard/results.json`. To regenerate and check both HTML files:

```sh
python3 scripts/build_leaderboard.py
python3 scripts/build_leaderboard.py --check
```

The site, Hugging Face Space, and results dataset share the same results
snapshot. Future snapshots are proposed through the submission repository.
