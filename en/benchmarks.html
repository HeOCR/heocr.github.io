Printed pages photographed by phone (PS-v1)

12 pages of printed modern Hebrew (legislation and prose), typeset by us from public-domain texts, printed and photographed by the maintainer with three phones. Held out: no model was trained, tuned or chosen on them. Character error (lower is better) per condition; the first photo of each page per phone counts.

On these real photos, heocr's own model is no better than stock Tesseract's model inside heocr, and heocr is slightly worse than plain Tesseract on flat photos. It finds more of the numbers.

Pointed print (niqqud) photographed by phone (NQ1)

25 pages of modern pointed Hebrew (poetry, Tanakh, and prose pointed by Dicta's nakdan), typeset by us in open fonts, printed and photographed twice in each of two sessions. Held out. Character error is shown with niqqud counted, and with niqqud removed from both sides (letters only); marks found is the share of vowel marks read correctly.

HeOCR's own models write no niqqud: pointed text comes out unpointed. On the letters alone they match stock Tesseract's model.

Handwriting

Scored 2026-11-20

225 handwritten Hebrew lines by 10 writers, photographed by phone, from ivrit.ai's Hebrew handwriting OCR benchmark (test split). Held out: no HeOCR model was trained, tuned or chosen on them. Each reader gets each line image as it is.

Handwriting is not supported yet. On these held-out lines every reader, ours included, gets most characters wrong. HeOCR's own model, trained on print, does worse here than stock Tesseract's model (+6.5 points of character error, 95% interval +4.5 to +8.7).

Method, reference and run
  • Measure: line_fold_v1 (text normalised the same way for every reader; ratios of sums over documents)
  • Reference: the release gate's fresh generated set (the cases of D-bench sets A, B and C, new seeds after the code freeze): generated documents with exact gold; text from the public-domain Israeli official gazette (Reshumot)
  • Licence: PD-IL (text)
  • Interval: 95% percentile bootstrap over documents, 2000 resamples, seed 0
  • Run: gate-rc2-synth-r2; heocr at 45241dc
  • Reader versions: Tesseract (tessdata_best heb) tesseract 5.5, heb tessdata_best e12c65a (sha256 dbaa827a), psm 3, pages at 300 dpi gray (pdftoppm); Docling 2.150.1; MarkItDown 0.1.9 [pdf,docx]; PyMuPDF4LLM 2.1 (AGPL; benchmark baseline only, decision 0020 item 2)
  • Left out: two office-scan cases rendered with a proprietary font (their scores cannot be published), and the provisional section-number case from the label measure
  • Scoring code: HeOCR's evaluation repository (not yet public; it is published with the release gate)

Release gate

The release gate scores a fresh set, made after the code is frozen. Each document type then gets one verdict: supported, or not supported. Run gate-rc2: heocr 0.2.0rc1 (commit 9d99d5e), scored 2026-11-20. The verdict is set by the one-sided 97.5% upper bound of heocr's difference from each other reader, against a fixed margin.
